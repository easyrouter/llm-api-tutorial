# 故障排查 A–G

验证失败时，诊断面板会直接指出属于下面哪一类，这里是完整说明。修完之后回到"验证"步骤再试一次。

## A. 401 / 403：认证失败

网关不认你的 Key。按顺序检查：

1. **多余的空格或换行。** 复制粘贴最容易在开头结尾带上空格、换行。回到 CC Switch 把 Key 删掉重新粘贴一次（可以先粘到记事本里看一眼）。
2. **激活的供应商不对。** CC Switch 里可能有多个供应商，新加的那个需要手动"切换"过去。看看列表里高亮/勾选的是哪一个。
3. **Key 本身。** 是否已过期、被撤销、还没开通，或者复制的是别的服务的 Key。到发放 Key 的平台确认状态，必要时重新申请。

## B. 404：地址不对

网关能连上，但路径不存在。地址处理规则：

- 结尾的 `/` 会被自动去掉；
- 只填域名（如 `https://gateway.example.com`）时会自动补上 `/v1`；
- 已经带 `/v1` 的地址原样使用；
- 结尾加 `#` 表示"按字面使用，别再追加任何路径"——只有网关明确要求时才用。

最稳妥的做法：回到本工具"配置"页，把显示的地址**原样复制**过去；那里的地址预览会显示最终生效的完整地址。

## C. 配置改了，但没有任何变化

几乎总是因为终端没关全。请关闭**所有**终端窗口和编辑器内置终端（最好把 VS Code / Cursor 整个退出），重新打开一个新终端再试。工具会在 Windows 上列出还在运行的终端进程。

## D. 环境变量冲突

如果系统里设置了 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_API_BASE`、`ANTHROPIC_API_KEY`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 等变量，命令行工具会**优先使用它们**，把 CC Switch 里的配置盖掉。本工具只负责发现和定位，**不会替你修改**：

- **Windows**：右键"此电脑"→"属性"→"高级系统设置"→"环境变量"。在"用户变量"和"系统变量"里分别找上面这些名字，选中后点"删除"（需要的话先记下值）。改完后关闭所有终端窗口重开。
- **macOS**：这些变量通常写在 `~/.zshrc` 或 `~/.zprofile`（bash 用户看 `~/.bash_profile`、`~/.bashrc`）。打开文件，找到 `export OPENAI_API_KEY=...` 之类的行，删掉或在行首加 `#` 注释掉，保存后关闭所有终端窗口重开。

工具"环境检查"页会标出每个变量来自哪里（注册表，或哪个文件的第几行）。

## E. 提示"命令不存在"（command not found / 不是内部或外部命令）

1. 刚装完还没关终端 → 关掉所有终端重开（同 C）。
2. Node.js 没装或版本太旧 → 回到"安装"步骤。
3. npm 的全局 bin 目录不在 PATH 里 → 在新终端执行 `npm prefix -g`，把输出的目录（Windows 直接用该目录；macOS 用其下的 `bin`）加入 PATH。工具会给出具体路径。

## F. 协议不匹配（400 / 422，或返回内容格式怪异）

Codex 使用 Responses 协议；服务网关支持并推荐 Responses，正常不会遇到。如果你连接的是**只支持 Chat Completions** 的其他服务，需要在 CC Switch 中启用它的本地代理进行协议转换，或者换用支持 Responses 的地址。

## G. 安装包被系统拦截

- **Windows SmartScreen**（"Windows 已保护你的电脑"）："更多信息"→"仍要运行"。
- **macOS Gatekeeper**（"无法验证开发者"/"已损坏"）："系统设置 → 隐私与安全性"，页面底部点"仍要打开"；或在终端执行 `xattr -d com.apple.quarantine /Applications/应用名.app`。

公司正式分发的安装包都经过签名，一般不会触发拦截；如果频繁遇到，请只从内网分发点下载。

## 都试过还是不行

在诊断面板点"导出诊断报告"，把生成的 Markdown 文件发给 IT 支持。报告里的 Key 和敏感信息已自动脱敏。
