# 一键操作说明

"环境检查"和"配置"页面上的一键按钮会**替你修改电脑上的东西**——装软件、改 PATH、删环境变量、写一个配置文件。每个按钮的工作方式都一样：

1. 先生成一份"计划"，把将要执行的命令或将要改动的内容**原样显示**给你；
2. 你点"确认"之后才真正执行；执行前工具会重新生成一遍计划并与你看到的那份比对，不一致就停下；
3. 凡是需要管理员权限的步骤，按钮上会写明"（需要管理员权限）"，并且弹出权限提示的是操作系统本身（Windows 的 UAC 对话框 / macOS 的密码框），不是本工具悄悄提权；
4. 会改动你文件的操作都先留备份，文件名形如 `原文件名.seedrouter-时间戳.bak`。

下面逐个说明每个按钮做了什么、怎么撤销。

## 一键安装 Node.js

**它做什么**
从官方站点或国内镜像下载当前的 Node.js LTS 安装包，校验完整性，然后运行官方安装程序。

**背后逐步操作**

1. 先探测网络：同时试探 `nodejs.org` 和 npmmirror 的 Node 镜像，选延迟最低、能连上的那个（都连不上时用第一个）。按钮和计划里会写明用了哪个源。
2. 从所选源下载 `index.json`（Node 的版本列表），挑出最新的 LTS 版本。
3. 按你的系统挑安装包：Windows 是 `node-v版本-x64.msi` 或 `node-v版本-arm64.msi`，macOS 是 `node-v版本.pkg`。文件保存在本工具的缓存目录 `downloads` 文件夹里。
4. 从**同一个源**下载 `SHASUMS256.txt`，用其中的 SHA-256 校验安装包；对不上就不会运行。
5. 运行安装程序：
   - **Windows**：`msiexec /i <安装包> /passive /norestart`。Windows Installer 会弹出 UAC 提示——这个 MSI 是"按机器安装"的，会把 Node.js 加进系统 PATH。你会看到一个进度条但不需要点"下一步"。退出码 3010 表示安装成功但需要重启才完全生效。
   - **macOS**：`osascript -e 'do shell script "installer -pkg <安装包> -target /" with administrator privileges'`。macOS 会弹出密码框，输入登录密码即可。
6. 装完后工具自动重新检查 Node.js。

**需要的权限**：管理员权限（UAC / macOS 密码）。提示由 Node.js 的安装程序触发。

**如何撤销**：Windows 在"设置 → 应用 → 已安装的应用"里卸载 Node.js；macOS 按 Node.js 官方说明删除 `/usr/local/bin/node`、`/usr/local/lib/node_modules` 等文件（需要 `sudo rm`）。缓存目录里的安装包可以随时删除。

**出错时怎么办**：校验失败 → 重新点一次，工具会重新下载；UAC / 密码框被取消 → 安装没有发生，可以稍后再点；提示"需要重启" → 重启后再"重新检查"；公司策略禁止安装 → 按"安装 Node.js"页面的便携版方式手动处理。

## 一键修复 PATH

**它做什么**
把某个目录（Node.js 所在目录，或 npm 全局命令所在目录）加进你的**用户级** PATH，让新打开的终端能找到 `node`、`codex`、`claude` 这些命令。

**它解决的问题**

- "Codex CLI 已找到但无法运行：`'"node"' 不是内部或外部命令`"——启动脚本找不到 `node`，因为 Node 目录不在 PATH 里。
- "安装成功，但重新检查仍然找不到命令"——npm 把命令装到了全局目录，可这个目录不在 PATH 里。

**背后逐步操作**

- **Windows**：把目录追加到 `HKCU\Environment\Path`（当前用户的 PATH，注册表里的 `REG_EXPAND_SZ` 类型保持不变，已有条目一个都不动），然后发送一次 `WM_SETTINGCHANGE` 广播，这样新开的终端会立刻拿到新的 PATH。计划里显示的是等价的 `reg add … /v Path …` 命令。**不会**改动系统级（所有用户）的 PATH。
- **macOS**：在你登录 shell 的配置文件末尾追加一行 `export PATH="<目录>:$PATH"  # added by SeedRouter Onboarding`（zsh → `~/.zshrc`，bash → `~/.bash_profile`，fish → `~/.config/fish/config.fish`，用的是 `fish_add_path`）。追加前先复制一份 `<文件>.seedrouter-<时间戳>.bak`。
- 如果目录已经在 PATH 里，计划会告诉你"已存在"，什么也不做。

**需要的权限**：不需要管理员权限。

**如何撤销**：Windows 在"系统属性 → 环境变量 → 用户变量 → Path"里删掉那一条；macOS 删掉带 `# added by SeedRouter Onboarding` 的那一行，或者用备份文件覆盖回去。

**出错时怎么办**：改完仍找不到命令 → 先关掉**所有**终端窗口再开新的（见"生效与验证"）；目录不存在 → 工具会拒绝计划，请先完成安装。

## 一键清理环境变量

**它做什么**
删除会覆盖 CC Switch 配置的环境变量（`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 等，见故障 D）。代理类变量（`HTTP_PROXY` 等）永远不会被碰。

**预览里为什么显示完整的值？**
因为这是删除操作。确认框会**故意把每个变量的完整值**（包括地址和令牌）显示出来，让你看清楚删的是什么、必要时先抄下来。这些值只出现在这个对话框里，不会写进日志、诊断报告或遥测。

**背后逐步操作**
工具先检查变量来自哪里，再对每个来源分别处理：

| 来源                                           | 操作                                                                                                    | 权限          |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------- |
| Windows 用户变量（`HKCU\Environment`）         | 删除该值（相当于 `reg delete "HKCU\Environment" /v 名称 /f`）                                           | 不需要        |
| Windows 系统变量（`HKLM\…\Environment`）       | 以管理员身份运行 `reg delete …`，会弹出 UAC                                                             | 管理员（UAC） |
| shell 配置文件 / PowerShell 配置文件里的某一行 | 先备份文件，再把那一行改成 `# removed by SeedRouter Onboarding: <原内容>`（注释掉，不删除）             | 不需要        |
| macOS `launchctl`                              | 执行 `launchctl unsetenv 名称`                                                                          | 不需要        |
| 只存在于当前进程（从启动它的程序继承来的）     | **无法删除**。说明是启动本工具的终端或程序带进来的；请从开始菜单 / 启动台重新打开本工具，或关掉那个终端 | —             |

处理完后自动重新检查环境变量。

**如何撤销**：配置文件用备份覆盖回去，或去掉那一行开头的注释；注册表里的值按"故障 D"的路径重新添加（你在预览里看到过完整值）。

**出错时怎么办**：UAC 被取消 → 系统变量没有删，其他来源照常处理，结果里会列出"失败"项；值在预览之后被别的程序改过 → 工具会拒绝删除这一项，重新点一次按钮看新值。

## 一键应用 config.toml

**它做什么**
把"配置"页生成的 Codex 配置模板写入 `~/.codex/config.toml`。模板让 Codex 通过服务网关工作，同时保留官方功能（priority 档位、大上下文、自动压缩）。这是本工具**唯一**会写入 `~/.codex/` 的文件，而且只在你点按钮之后。

**背后逐步操作**

1. 页面上显示的模板里，API Key 的位置是占位符 `<API-KEY>`；点"应用"时才在本机内存中把真实 Key 代入，**界面上从不显示真实 Key**。
2. 工具检查内容是合法的 TOML。
3. 如果 `~/.codex/config.toml` 已存在，先复制为 `config.toml.seedrouter-<时间戳>.bak`。
4. 写入新文件。结果里显示路径、字节数和备份文件名。

**需要的权限**：不需要管理员权限（文件在你的用户目录里）。

**如何撤销**：点"恢复上一个备份"，工具把最新的备份放回去（恢复前会把当前文件也备份一份，所以这个操作本身也能反悔）。

**出错时怎么办**

- **CC Switch 切换供应商时可能会重写这个文件**——这是 CC Switch 的正常行为。切换之后回到"配置"页再点一次"应用"即可；页面会提示"与模板不一致"。
- Key 还没填 → 按钮不可用，先在上面的卡片里粘贴 Key。
- 文件被占用 / 没有权限 → 关闭正在运行的 Codex 后重试。

## 安装 Codex 客户端

**它做什么**
安装 Codex 桌面客户端（现在包含在 **ChatGPT** 桌面应用里）。这一步**可选但推荐**：命令行的 Codex CLI 不依赖它，但桌面客户端更适合非开发者。

**背后逐步操作**

- **Windows，推荐**：点"打开 Microsoft Store"，跳到 Store 里的 ChatGPT 应用页面（产品编号 `9PLM9XGG6VKS`），在 Store 里点"获取"。
- **Windows，离线安装包**：下载 OpenAI 签名的 MSIX（约 745 MB），然后运行 `powershell Add-AppxPackage -Path <文件>`。这是按当前用户安装，**不需要管理员权限**。
- **Store 提示"此应用在你所在的地区不可用"**：点"打开 Windows 区域设置"（`ms-settings:regionformatting`），把"国家或地区"改成可用的地区，关闭再重新打开 Store；之后可以改回来。
- **macOS**：下载 DMG（约 650 MB），工具把它挂载、将 `.app` 复制到 `/Applications`、再卸载镜像。属于"管理员"组的用户不需要输密码。手动替代：双击 DMG，把应用拖进"应用程序"文件夹。
- 任何一步都可以改为手动：点"打开下载页"去官网下载。

**需要的权限**：Store 和 MSIX 安装不需要管理员权限；macOS 拖入"应用程序"也不需要（标准用户账号可能会被系统要求输入管理员密码）。

**如何撤销**：Windows 在"设置 → 应用"里卸载"ChatGPT"；macOS 把 `/Applications/ChatGPT.app` 拖进废纸篓。

**出错时怎么办**：`Add-AppxPackage` 报"签名不受信任" → 说明下载被篡改或不完整，删除后重新下载，或改用 Store；下载很慢 → 这是大文件，可先用 Store；Store 打不开 → 用离线安装包。

## 权限说明

- 本工具**从不静默提权**。需要管理员权限的只有两类操作：运行 Node.js 官方安装程序（MSI / pkg），以及删除 Windows **系统级**环境变量。两者的提示框都由操作系统或安装程序本身弹出（UAC、macOS 密码框），按钮上会写明"（需要管理员权限）"。
- 其余一键操作（修复用户 PATH、删除用户变量、注释配置文件、写 `config.toml`、安装 Codex 客户端）都只动你自己的用户目录和用户级设置。
- 本工具**从不**写入 `~/.claude/`、`~/.cc-switch/`，也不改动系统级（所有用户）的 PATH。
- 所有被改动的文件都有 `.seedrouter-<时间戳>.bak` 备份；所有已执行的命令都会记录到本工具的日志里（其中的密钥和令牌会被脱敏）。
