# 常见问题

**这个工具和 CC Switch 是什么关系？**
CC Switch 负责"配置"，本工具负责"把整个流程串起来"：检查环境、装缺的东西、告诉你在 CC Switch 里填什么、验证结果、失败时诊断。工具不会替代 CC Switch，也不会碰它的数据。

**我只用 Codex，不用 Claude Code（或者反过来），怎么办？**
在向导开头只勾选你需要的工具即可，后面的安装、配置和验证只针对你选的那个。

**工具会保存我的 API Key 吗？**
不会。Key 只在你点"验证"发起连通性测试时短暂存在于内存中，请求结束就丢弃；不会写入磁盘、日志、诊断报告或遥测。CC Switch 会把 Key 写入各工具自己的配置文件，那是它的正常职责。

**为什么要我关掉所有终端窗口？**
终端在打开时会复制一份当时的环境（PATH、环境变量），之后不再更新。安装和配置之后不重开终端，就会出现"命令不存在"或"配置没生效"。这是最常见的问题，所以工具会反复提醒。

**没有管理员权限能完成吗？**
大部分步骤可以：npm 全局安装默认在用户目录；CC Switch 的 Windows 安装包支持当前用户安装；Codex 客户端的 Store / MSIX 安装按当前用户进行；修复 PATH、清理用户变量、写 `config.toml` 都只动你的用户目录；本工具自身也是按当前用户安装。只有两件事需要管理员权限："一键安装 Node.js"（官方 MSI / pkg 安装程序会弹出 UAC / 密码框）和删除 Windows **系统级**环境变量（`reg delete` 以管理员身份运行，UAC）。这些按钮上都写着"（需要管理员权限）"，提示框由系统弹出，工具不会静默提权。没有管理员权限时 Node.js 可以改用便携版。

**工具会在我的电脑上写什么、改什么？**
只有你点了一键按钮之后才会改，而且每次都先显示计划：

- 用户 PATH（Windows `HKCU\Environment\Path`；macOS 你的 shell 配置文件末尾追加一行，先备份）；
- 删除冲突的环境变量（用户变量、系统变量需 UAC、配置文件里注释掉那一行并备份、`launchctl unsetenv`）；
- `~/.codex/config.toml`（先备份为 `config.toml.seedrouter-<时间戳>.bak`，可一键恢复）；
- 运行下载到缓存目录的安装包（Node.js、Codex 客户端）。

工具**从不**写 `~/.claude/`、`~/.cc-switch/`，从不改系统级 PATH，从不记录你的 Key。详见"一键操作说明"。

**办公网络访问不了 npm 官方源怎么办？**
工具会自动测速并切换到国内镜像（npmmirror），要执行的命令里会明确写出所用的源。

**模型名要填什么？**
服务网关只有地址是统一的，模型名和推理强度因人而异。填你被分配的模型名；不确定就先用工具给出的建议值，之后可以随时在 CC Switch 里改。

**以后 Codex / Claude Code 出新版本了怎么升级？**
在新终端里重新执行一次 `npm install -g @openai/codex`（或 `@anthropic-ai/claude-code`）即可。CC Switch 在应用内有更新提示。

**工具会自动更新吗？**
不会。新版本请从公司内网分发点或官网下载。

**遥测收集了什么？**
默认关闭，只有 IT 配置了内网端点并且你没有关闭时才会发送。内容只有匿名的步骤成功/失败、耗时、错误类别和诊断规则编号，没有主机名、用户名、地址、路径、Key 或任何自由文本。可以在设置里随时关闭。

**报告里有敏感信息吗？**
诊断报告在生成时会把 Key、令牌、带凭据的地址统一替换成 `[REDACTED]`，可以直接发给 IT。
