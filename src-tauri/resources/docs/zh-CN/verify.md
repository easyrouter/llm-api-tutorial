# 生效与验证

## 先做一件事：关掉所有终端窗口

这是整份指南里**最常见**的问题来源。安装和配置改动的是 PATH 环境变量和配置文件，而每个终端窗口在打开的那一刻就把当时的环境复制了一份并一直用下去。所以：

- 已经打开的终端不知道 `codex` / `claude` 命令刚被装上 → 报"命令不存在"；
- 已经打开的终端里可能仍带着旧的环境变量 → 配置"没效果"。

请把**所有**终端窗口都关掉，包括：Windows Terminal、PowerShell、CMD、Git Bash、macOS 的"终端"和 iTerm，以及 **VS Code、Cursor 等编辑器里的内置终端**（最保险的做法是把编辑器整个关掉）。工具会在 Windows 上列出仍在运行的终端进程提醒你。

## 一键验证做了什么

点"开始验证"后，工具会：

1. 在一个**全新的会话**里执行 `codex --version` 或 `claude --version`（模拟你新开一个终端），确认命令能找到并能运行。
2. （可选）向公司网关发一条最小的测试请求，确认地址、协议和 Key 都正确。这一步需要你临时输入 API Key；Key 只在内存中保留这一次请求的时间，不会保存、记录或上传。
3. 直接告诉你**成功**或**失败**。失败时自动打开诊断面板，给出具体是哪一类问题（A–G）以及修复步骤。

## 自己在终端里测试

如果想亲眼确认，打开一个**新的**终端窗口：

```
codex --version
codex "用一句话介绍你自己"
```

或

```
claude --version
claude "用一句话介绍你自己"
```

能看到版本号并且收到回复，就说明全部打通了。

## 验证失败？

不用自己去对照错误码，看诊断面板给出的结论即可。常见对应关系：

- 401 / 403 → Key 有问题（故障 A）
- 404 → 地址有问题（故障 B）
- 命令不存在 → PATH 没刷新或没装好（故障 E）
- 配了但没效果 → 终端没关全（故障 C）或环境变量冲突（故障 D）

修完后回到这一步再点一次"开始验证"。
